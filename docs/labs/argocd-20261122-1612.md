## 참고 (시험 뒤 손으로 덧붙임)

- **DNS 지연 가능성:** Application의 `repoURL`이 점 4개짜리 긴 서비스 이름(`gitea.k3slab-system.svc.cluster.local`)이다. 관측 세션이 이런 이름은 검색 도메인 `localdomain` 때문에
  약 10초 늦어지거나 실패할 수 있다는 것을 찾았고, 플랫폼 세션이 coredns-custom으로 고치는 중이다. 그래서 위 "처음 동기화 21초"와 "values 커밋 → 새 파드 Ready 55초"에는
  이 지연이 들어 있을 수 있다. 매니페스트는 그대로 두었고, 고친 뒤 CICD_연결에서 다시 잰다.
- **메모리 측정 시점:** 5절의 값은 시험이 끝나기 직전 한 번 읽은 `kubectl top`(작업 집합) 값이다. 최대값(peak)이 아니다. 같은 파드를 시험 전(Application 없음)에 읽으면
  controller 26, redis 9, repo-server 24, server 42, gitea 104 MiB였다.
- **시험 중 나온 경고 한 줄:** `kubectl apply`가 Application의 파이널라이저 이름(`resources-finalizer.argocd.argoproj.io`)에 "도메인 이름 형식을 쓰라"는 경고를 냈다.
  Argo CD 공식 문서의 이름이고 동작에는 영향이 없었다.
- **자가 치유 시간(2초, 1초):** 확인 주기(30초)를 기다리지 않는다. Argo CD가 객체 변경을 바로 보고 동기화하기 때문이다. 반면 Git 커밋은 확인 주기(30초 + 지터 5초)와 파드 교체 시간(GPU 파드라 예전 파드를 먼저 내리고, preStop 5초 포함)이 합쳐져 55초가 걸렸다. 두 시간을 나눠서 재지는 않았다.
